# PRD：Git Switch —— 本地 Git 配置切换工具

> 状态：v1.0（定稿，进入开发）
> 开发进度：M1 ✅ 已完成 / M2 ✅ 已完成 / M3 ✅ 已完成
> 日期：2026-XX-XX

## 1. 背景与问题

开发者通常持有多套 Git 身份（工作 / 个人 / 开源）和不同的项目级配置诉求。现状下：

- 手动编辑 `~/.gitconfig`（`%USERPROFILE%\.gitconfig`）和各个仓库的 `.git/config`，容易改错、忘记切换、污染配置。
- git 原生的 `includeIf` 机制可以实现按目录自动加载配置，但语法手写、路径规则易错，且没有可视化手段管理。
- 缺少对"切换前备份 / 回滚"的支持，改坏配置后难以恢复。

## 2. 目标

构建一个 **Windows 桌面 GUI 工具**（Electron），实现：

1. **多身份/多配置集一键切换**（全局级）。
2. **项目级配置管理**（对任意仓库单独查看/编辑 `.git/config`）。
3. **按目录自动切换**（基于 `includeIf gitdir:`，可视化管理映射关系）。
4. **配置浏览器**（图形化查看/编辑所有配置项，标注来源 scope）。

## 3. 目标用户与场景

| 用户 | 典型场景 |
|---|---|
| 身兼多职的开发者 | 工作仓库用公司邮箱+签名密钥，个人项目用私人邮箱，手工切换繁琐 |
| 团队协作成员 | 某些仓库需要不同的 `user.name` 或提交签名配置 |
| 经常 clone 到不同目录的开发者 | 希望进入特定目录自动套用对应身份，不用记 |

## 4. 功能需求

### 4.1 配置集（Profile）管理 —— M1 核心

- **配置集 CRUD**：创建 / 编辑 / 删除 / 复制"配置集"。
  - 每个配置集包含一组 key-value 配置项（`user.name`、`user.email`、`user.signingkey`、`commit.gpgsign`、`http.proxy` 等任意项）。
  - 提供**常用项模板**（身份类：name/email/signingkey/gpgsign；扩展类：代理、行为偏好如 `core.autocrlf`、`init.defaultBranch`），同时支持**任意自定义 key**。
- **一键应用到全局**：把配置集内容写入全局配置（`--global` scope）。
  - 应用方式（已确认）：**覆盖同名项 + 保留无关项**——只写入/覆盖配置集中存在的 key，全局配置中其余项原样保留；配置集中为空的项不产生任何写入。
- **一键应用到项目**：把配置集内容写入指定仓库的 `--local` scope。
- **激活状态展示**：当前全局生效的配置集高亮显示。

### 4.2 项目级配置管理 —— M1

- 选择任意文件夹，检测是否为 git 仓库（含非裸仓库、`git rev-parse` 校验）。
- 以表格/表单形式查看该仓库的 **local scope** 配置，支持编辑、删除、新增配置项。
- 支持"将此配置集应用到此仓库"（写 local scope）。
- 展示该仓库最终生效的配置（global + local 合并视图，标注来源）。

### 4.3 按目录自动切换（includeIf）—— M2

- 可视化管理 `includeIf` 映射：**目录（支持 `gitdir:` 语法 / 普通绝对路径 / `~/` 缩写 / `**` 通配）→ 配置集**。
- 应用写入全局配置：
  ```
  [includeIf "gitdir:D:/work/"]
      path = %USERPROFILE%\.gitconfig-<profile-id>
  ```
- 每个配置集对应独立文件（`~/.gitconfig-<profile-id>`），由 includeIf 引用，**不污染**全局配置主体。
- 冲突检测与提示：多个规则匹配同一目录时，按规则定义顺序提示优先级/覆盖关系（git 按文件内顺序依次 include，后者覆盖前者），并在 UI 中标注可能被覆盖的规则。
- 目录规则支持开关（临时禁用某条映射而不删除）。

### 4.4 配置浏览器 —— M1

- 列出 system / global / local 三层的全部配置项（`git config --list --show-origin --show-scope`）。
- 每条记录标注**来源 scope 与配置文件路径**，支持按 scope / 关键字过滤搜索。
- 支持新增、编辑、删除配置项（写入对应 scope 文件）。
- **脱敏显示**：对敏感项（如 `http.<url>.extraHeader`、含密码的 proxy URL、credential 相关）默认打码，可手动切换明文。

### 4.5 备份与回滚 —— M1

- 每次"切换 / 写入"操作前，自动备份将被修改的配置文件（`%USERPROFILE%\.gitconfig`、仓库 `.git/config`、`.gitconfig-<profile-id>` 等）到 `%APPDATA%\git-switch\backup\<timestamp>\`。
- 提供"历史备份列表"，支持一键**回滚**到任意备份点。
- 操作日志：记录每次切换的时间、来源、目标，便于排查。

### 4.6 系统托盘 —— M2

- 托盘菜单列出全部配置集，点击即一键应用到全局（无需打开主窗口）。
- 托盘图标/标题显示当前生效的配置集名称；托盘菜单支持快速回到主窗口、退出。

### 4.7 生效值对照面板 —— M1

- 提供**实际生效值总览**：把 system / global / local / includeIf 多层配置叠加后，展示每个 key 的最终生效值（等价于 `git config --list` 的合并视图，标注每项来自哪个 scope/文件）。
- 支持按 key 搜索，点击任意 key 可下钻查看各层原始值与覆盖链。

### 4.8 首次启动引导（Onboarding）—— M1

- 首次启动流程：检测 `git.exe` 是否可用（常见安装路径 + PATH），缺失时给出下载指引（git-scm.com）与重试按钮。
- 引导创建第一个配置集（填写 name/email 等），随后可选择应用到全局。
- 提供示例配置集（如"工作/个人"预填模板）一键创建。
- 引导完成后展示主界面，之后可通过设置重新打开引导。

### 4.9 导入 / 导出 —— M3

- 配置集可导出为 JSON / 剪贴板文本，换机后可导入。
- 导出时敏感项默认脱敏，可显式选择包含明文。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 平台 | 仅 Windows（优先 Win10/11），路径处理兼容 `C:\`、`~/`、UNC 等 |
| Git 依赖 | 依赖已安装 Git for Windows；启动时检测 `git.exe`（常见安装路径 + PATH），缺失时给出引导 |
| 安全性 | 不存储明文凭据；敏感项脱敏；操作前备份；配置文件写入使用原子写入 |
| 可靠性 | 写配置前校验语法（`git config --file` 可解析性），失败则中止并保留备份 |
| 性能 | 常规操作（列表/切换）< 1s；配置浏览器懒加载大文件 |
| 易用性 | 中文界面；操作均有确认与可回滚提示 |
| 视觉 | **默认深色主题 + 透明玻璃拟态（Glassmorphism）科技感**；浅色主题可切换；跟随系统可选用 |

## 6. 技术方案概要

- **框架**：Electron（主进程负责 git 命令执行与文件 IO；渲染进程 UI）。
  - 安全基线：`contextIsolation: true`、`nodeIntegration: false`、preload 通过 `contextBridge` 暴露受限 API。
- **与 Git 交互**：主进程通过 `child_process` 调用 `git config` 命令族：
  - 读取：`git config --list --show-origin --show-scope --null`
  - 写入/删除：`git config --global|--local|--file <file> <key> <value>` / `--unset`
  - 直接读写 `.gitconfig` 文件保留注释与格式（备份用）。
- **应用自身数据**（配置集、includeIf 映射、备份记录）存于 `%APPDATA%\git-switch\`，采用 **JSON 文件**（配置集 `profiles.json`、映射 `includes.json`、备份元数据 `backups.json`）。
- **前端**：**React + Ant Design**（已确认）。
  - 主题：默认深色，叠加透明玻璃拟态（毛玻璃背景、半透明面板、模糊层、发光强调色）；Ant Design ConfigProvider 的 darkAlgorithm + 自定义 CSS 变量实现，支持浅色切换。

## 8. 边界（暂不做）

- 不做 git 凭据管理器（credentials）的密码存取，仅管理配置项。
- 不做系统级（system scope）配置的编辑 UI（可查看），避免权限与污染风险。
- 不做多用户/多实例同步（云端同步不在本期范围）。
- 不做 CLI 入口（本期仅 GUI；CLI 留待后续版本评估）。
